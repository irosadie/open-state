## Why

The current backend (`apps/api`) and worker (`apps/worker`) are built on Node.js/TypeScript with Hono and BullMQ. Migrating to Go (Echo + sqlc + goose) delivers better runtime performance, a smaller production footprint, and a type-safe, no-magic database layer that is easier to reason about in production. The `packages/schemas` Zod schemas cannot be shared across language boundaries, so they will be converted to language-native equivalents on each side.

## What Changes

- **BREAKING** — `apps/api` rewritten in Go using **Echo** framework, **sqlc** for type-safe SQL queries, and **goose** for migrations. Replaces Hono + Prisma + TypeScript.
- **BREAKING** — `apps/worker` rewritten in Go using **asynq** (Redis-based job queue, idiomatic Go replacement for BullMQ). Replaces BullMQ + TypeScript.
- **BREAKING** — `packages/schemas` Zod schemas are no longer shared with the backend. Frontend (`apps/web`) keeps its own Zod schemas in `packages/schemas`. Backend defines equivalent Go structs generated by sqlc and validated inline.
- `packages/types` TypeScript API response types remain — still consumed by `apps/web`.
- `packages/utils` remains TypeScript — only used by frontend and tooling.
- Prisma and `@prisma/client` removed from `apps/api`. Database migrations moved to `apps/api/db/migrations/` managed by goose.
- `turbo.json` and root `package.json` updated to exclude Go apps from TypeScript build pipeline. Go apps are built via `go build` independently.
- Docker setup for `apps/api` and `apps/worker` updated to use Go multi-stage builds.

## Capabilities

### New Capabilities

- `backend/http-server`: Echo-based HTTP server with middleware chain, centralized error handler, and request lifecycle (replaces Hono app in `apps/api`)
- `backend/auth`: Auth domain in Go — register, login, logout, get-current-user use cases with JWT + session (replaces existing TypeScript auth domain)
- `backend/database`: sqlc query layer + goose migration setup for PostgreSQL (replaces Prisma)
- `backend/worker`: asynq-based background worker in Go (replaces BullMQ worker in `apps/worker`)
- `backend/domain-error`: Go DomainError type + Echo error handler mapping to HTTP status codes (replaces TypeScript DomainError + Hono errorHandler)

### Modified Capabilities

- `frontend/api-contract`: `packages/schemas` no longer shared with backend. Frontend Zod schemas remain but backend contract is now defined by Go structs + OpenAPI docs only.

## Impact

- **`apps/api`** — full rewrite in Go. New folder structure:
  ```
  apps/api/
  ├── cmd/server/         → main entrypoint
  ├── internal/
  │   ├── domain/         → entities, repository interfaces, domain errors
  │   ├── application/    → use cases, services
  │   ├── infrastructure/ → sqlc queries, goose migrations, service impls
  │   └── interfaces/     → Echo routes, controllers, middleware
  ├── db/
  │   ├── migrations/     → goose SQL migration files
  │   └── queries/        → sqlc .sql query files
  └── sqlc.yaml
  ```
- **`apps/worker`** — full rewrite in Go. New folder structure:
  ```
  apps/worker/
  ├── cmd/worker/         → main entrypoint
  ├── internal/
  │   ├── application/    → job handlers / use cases
  │   └── infrastructure/ → asynq worker registration
  └── go.mod
  ```
- **`packages/schemas`** — Zod schemas remain for frontend use only. Remove any backend-only schemas.
- **`packages/types`** — no change.
- **`turbo.json`** — Go apps excluded from TypeScript pipeline.
- **`docker-compose.yml`** — service images updated for Go builds.
- **Dependencies removed**: `hono`, `@hono/*`, `@prisma/client`, `prisma`, `bullmq`, `@types/node` (from api/worker).
- **Dependencies added**: Go modules — `github.com/labstack/echo/v4`, `github.com/sqlc-dev/sqlc`, `github.com/pressly/goose/v3`, `github.com/hibiken/asynq`, `github.com/golang-jwt/jwt/v5`, `github.com/jackc/pgx/v5`.
